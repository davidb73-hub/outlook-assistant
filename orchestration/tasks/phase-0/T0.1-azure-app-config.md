# T0.1 — Azure App Registration + Local MCP Config

**Phase:** 0 · **Owner agent:** `golive-operator` · 👤 **Owner required:** yes (Azure portal, secrets)
**Global rules:** `orchestration/EXECUTOR-GUIDE.md` §1. **Sources:** `HANDOVER.md` §"Azure Setup Checklist" and §"Recommended Next Step"; `CLAUDE.md` §"Authentication" and §"Configuration"; `.env.example`.

## Objective

A registered Azure/Entra app and a local (never-committed) MCP client config such that the server can start device-code auth, with all send-safety env vars set from day one.

## Steps

1. **👤 Owner, in Azure Portal → App registrations** (executor provides this checklist, owner executes — from `HANDOVER.md`):
   - New (or existing) registration; supported account type: *Accounts in any organizational directory and personal Microsoft accounts* (matches default `OUTLOOK_AUTH_AUDIENCE=common`). If the owner instead registers personal-only or single-tenant, record the matching `OUTLOOK_AUTH_AUDIENCE` value (`consumers` / tenant GUID) for step 3.
   - Add platform: *Mobile and desktop applications*; check redirect URI `https://login.microsoftonline.com/common/oauth2/nativeclient`.
   - Authentication → Advanced settings → **Allow public client flows: Yes** (device-code requires this; failure mode is `invalid_client`, see `HANDOVER.md` §"Common Auth Failures").
   - API permissions → Microsoft Graph → Delegated: `offline_access`, `User.Read`, `Mail.Read`, `Mail.ReadWrite`, `Mail.Send`, `Calendars.Read`, `Calendars.ReadWrite`, `Contacts.Read`, `Contacts.ReadWrite`, `People.Read`, `MailboxSettings.ReadWrite` (this exact list is `AUTH_CONFIG.scopes`, `config.js:81-96`). Optional, work/school only: `Mail.Read.Shared`, `Place.Read.All`.
   - Copy the **Application (client) ID**. A client secret is not required for device-code public-client flow (`HANDOVER.md`); if created anyway, copy the secret **Value**, not the Secret ID (`AADSTS7000215` trap).
2. **Record the account type** (personal Microsoft account vs work/school) the owner will sign in with — Phase 2 gating depends on it.
3. **Executor: write the local MCP client config** (Claude Desktop/Code MCP settings — outside this repo), shape from `HANDOVER.md`:

   ```json
   {
     "mcpServers": {
       "outlook": {
         "command": "node",
         "args": ["/Users/davidbasseal/Developer/EMAIL-Assistant-Repos/outlook-assistant/index.js"],
         "env": {
           "OUTLOOK_CLIENT_ID": "<application-client-id>",
           "OUTLOOK_AUTH_METHOD": "device-code",
           "OUTLOOK_MAX_EMAILS_PER_SESSION": "10",
           "OUTLOOK_ALLOWED_RECIPIENTS": "<owner-address>",
           "OUTLOOK_DEFAULT_TIMEZONE": "Australia/Sydney"
         }
       }
     }
   }
   ```

   `OUTLOOK_ALLOWED_RECIPIENTS` starts as **exactly the owner's own address** — Phase 0 needs no other recipient; widen later deliberately. Add `OUTLOOK_AUTH_AUDIENCE` only if step 1 chose a non-`common` registration (`CLAUDE.md` §"Configuration").
4. Append to `orchestration/STATE.md`: date, client ID's **last 4 characters only**, account type, audience chosen, env vars set (names, not secret values).

## Acceptance criteria (runnable)

| Check | Command | Expected |
|-------|---------|----------|
| No secrets entered the repo | `git status --short` and `git diff` in the repo | No new/modified files except `orchestration/STATE.md`; no client ID/secret strings in it beyond last-4 |
| Server starts with the config's env | `OUTLOOK_CLIENT_ID=<id> USE_TEST_MODE=true npm run test-mode` (Ctrl-C after banner) | Startup without the `TokenStorage: OUTLOOK_CLIENT_ID is not configured` warning noted in `HANDOVER.md` §"Verification Evidence" |
| Safety env vars present in MCP config | Read the MCP config file | `OUTLOOK_MAX_EMAILS_PER_SESSION` and `OUTLOOK_ALLOWED_RECIPIENTS` both set, allowlist = owner's address only |
| STATE.md updated | `grep "T0.1" orchestration/STATE.md` | Entry with date, account type, audience |

## Files in scope / must not change

- **May create/edit:** local MCP client config (outside repo), `orchestration/STATE.md`.
- **Must not change:** anything else in the repo. **Never commit:** client ID/secret, tokens, `.env` files (`.gitignore` and EXECUTOR-GUIDE §1.6).
