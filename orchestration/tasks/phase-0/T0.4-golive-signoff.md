# T0.4 — Go-Live Sign-Off + Docs Sync

**Phase:** 0 · **Owner agents:** `golive-operator` (checklist), `docs-maintainer` (docs drift), `reviewer` (gate on any PR) · 👤 **Owner required:** yes (final sign-off)
**Depends on:** T0.1–T0.3 gates recorded in `orchestration/STATE.md`.

## Objective

Declare the server production-live with an evidence-backed checklist, and fix any documentation drift discovered during Phase 0.

## Steps

1. **Compile the sign-off checklist** in `orchestration/STATE.md` — every line must reference the STATE.md evidence entry that proves it:

   ```
   T0.4 GO-LIVE SIGN-OFF (date, executor)
   [ ] Baseline verified pre-phase: 29 suites / 751 tests, lint 0 errors     (T0 step-0 entry)
   [ ] Azure app registered; public client flow on; scopes match config.js  (T0.1)
   [ ] No secrets in repo (git log/status audited)                          (T0.1)
   [ ] Device-code auth completed; tokens auto-refresh in place             (T0.2)
   [ ] All 6 read-only smoke checks passed                                  (T0.2)
   [ ] dryRun preview verified                                              (T0.3 #1)
   [ ] Allowlist block verified                                             (T0.3 #2)
   [ ] Rate limit verified; exactly 1 live email sent, to owner             (T0.3 #3)
   [ ] Safety env vars restored to production values                        (T0.3 #4)
   [ ] Owner sign-off: <name, date>
   ```

2. **Docs drift pass** (`docs-maintainer`): compare what Phase 0 actually observed against `HANDOVER.md` §"Common Auth Failures", `docs/troubleshooting.md`, and `docs/how-to/getting-started/` content. Any error hit in T0.2/T0.3 that lacked a documented fix, or any documented step that didn't match reality, becomes a docs update. Check `.claude/rules/faq-maintenance.md` triggers — Phase 0 changes no code, so normally none fire; a discovered auth-doc inaccuracy may still warrant a FAQ answer fix (targeted Edit only, ≥7 H2s).
3. **HANDOVER.md update** (`docs-maintainer`): replace §"Recommended Next Step" ("Do not build more features yet…") with the post-go-live state: live since <date>, evidence in `orchestration/STATE.md`, next phase per `orchestration/00-SCOPE-PROPOSAL.md` Phase 1. Keep the Azure checklist and failure table — they remain useful for re-auth.
4. **PR + review:** steps 2–3 land as one `docs:`-typed PR (branch `docs/phase-0-golive-signoff`), gated by `reviewer` per `orchestration/agents/reviewer.md`, plus the STATE.md checklist commit. 👤 Owner ticks the final sign-off line.

## Acceptance criteria (runnable)

| Check | Command | Expected |
|-------|---------|----------|
| Checklist complete | `grep -A12 "GO-LIVE SIGN-OFF" orchestration/STATE.md` | Every box `[x]`, owner line filled |
| Docs PR merged (if drift found) or explicit "no drift" entry | `git log --oneline -5` / STATE.md | `docs:` merge visible or `T0.4: no docs drift found` line |
| Suite untouched by Phase 0 | `npm test` → tail | `Test Suites: 29 passed` / `Tests: 751 passed` |
| Lint clean | `npm run lint` → tail | `0 errors` |
| FAQ floor intact | `grep -cE '^## ' docs/faq/faq.md` | ≥ 7 (currently 11) |

## Files in scope / must not change

- **May edit:** `orchestration/STATE.md`, `HANDOVER.md`, `docs/troubleshooting.md`, `docs/how-to/getting-started/**`, `docs/faq/faq.md` (targeted Edit only), `CHANGELOG.md` (docs-fix entries under `[Unreleased]`).
- **Must not change:** any `.js` source or test file; `utils/safety.js`; tool annotations. A code defect found in Phase 0 is filed as a GitHub issue and queued, not fixed here.
