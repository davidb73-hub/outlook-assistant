# T0.2 — Device-Code Authentication + Read-Only Live Smoke Test

**Phase:** 0 · **Owner agent:** `golive-operator` · 👤 **Owner required:** yes (browser sign-in, once)
**Depends on:** T0.1 gate recorded in `orchestration/STATE.md`.
**Sources:** `CLAUDE.md` §"Authentication Flow"; `HANDOVER.md` §"Live Smoke Test Order" and §"Common Auth Failures"; `docs/troubleshooting.md`; `orchestration/EXECUTOR-GUIDE.md` §4.

## Objective

Valid tokens on disk and all six read-only smoke checks passing against the live mailbox. **No mutating call of any kind in this task.**

## Steps

1. **Authenticate (device-code, the repo default — `config.js:103`):**
   1. Call tool `auth` with `{"action":"authenticate"}` → returns a URL + user code.
   2. 👤 Owner: open the URL **in a private/incognito browser** (cached-session interference, `CLAUDE.md` §"Azure prerequisites"), enter the code, sign in with the account recorded in T0.1.
   3. Call tool `auth` with `{"action":"device-code-complete"}` → tokens saved. This call polls; allow 10–15 s (`docs/troubleshooting.md` "device-code-complete hangs").
2. **Token sanity (redacted — never print token values):**

   ```bash
   cat ~/.outlook-assistant-tokens.json | python3 -c "import json,sys; t=json.load(sys.stdin); print('auth_method:', t.get('auth_method')); print('expires_at:', t.get('expires_at')); print('has access_token:', bool(t.get('access_token')))"
   ```

   (verbatim from `docs/troubleshooting.md` §"Checking Authentication State".)
3. **Run the six read-only checks in order** (EXECUTOR-GUIDE §4 — the HANDOVER order). Record each tool call and a one-line result summary (counts/subjects, not full bodies) in `orchestration/STATE.md`.
4. On any failure: match the error against `HANDOVER.md` §"Common Auth Failures" / `docs/troubleshooting.md`; apply the listed fix; max 3 retries per distinct error; unknown error → stop and report (EXECUTOR-GUIDE §1.10). Full reset if tokens are stuck: `rm ~/.outlook-assistant-tokens.json ~/.outlook-assistant-pending-auth.json`, restart from step 1.
